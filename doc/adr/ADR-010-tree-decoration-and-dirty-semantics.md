# ADR-010：树标签组合与 dirty 语义

- 状态：已接受并实现。
- 依据：Phase 2 §1、§5；禁用标签时 Phase 1 `tree` 输出逐字节不变。

## 标签边界

比较两种实现：

| 方案                                         | 收益                                                                   | 代价与风险                                                                         |
| -------------------------------------------- | ---------------------------------------------------------------------- | ---------------------------------------------------------------------------------- |
| 装饰器包装完整格式化器，再解析或重建输出行   | 形式上接近经典 Decorator                                               | 插件必须知道树枝字符、列对齐和“一节点一行”等宿主排版细节，新增标签可能复制格式化器 |
| 核心定义语义行目标，注册装饰器只返回行尾标签 | 插件只看画布或 `ShapeView`；宿主仍独占遍历和排版；标签可按注册顺序组合 | `TreeFormatter` 需一次性接入通用标签注册表                                         |

选择第二种。`TreeDecorator` 有稳定名称，并针对只读的画布行或图形行返回一个可选标签；它不接触文档、CLI 字符串或其他装饰器。注册表按登记顺序调用并以单个空格连接非空标签，重名报 `duplicate registration: decorators/<name>`，空白或含换行的标签报契约错误。无注册项时不添加空格，保持 Phase 1 字节输出。标签扩展只涉及插件及装配，不修改核心模型或 `TreeFormatter`。

## dirty 状态

`modified-star` 采用“当前语义树与最近成功 init/read/save 基线是否不同”的保存点语义，而不是“发生过编辑命令”的事件语义。因此 undo 回到保存点后 `*` 消失，redo 后重新出现；新建节点相对基线立即标记；子节点变化时该节点及其祖先容器标记，未受影响的兄弟不标记；画布尺寸或任一节点不同则画布行标记。

装饰器实例持有自己的基线快照，不使用模块级变量。注册表只在 init、完整 read 成功以及 write 成功后通知装饰器重置基线；失败的读写不改变基线。通用契约不预建事件总线，渲染时由装饰器比较当前只读投影。多个标签按注册顺序拼接，例如先注册 `modified-star`、后注册 box 标签时输出 `g#n1 * (box)`。

接口、注册、格式化调用和基线通知均已实现；`modified-star` 与 box 标签作为彼此独立的插件按注册顺序组合。测试覆盖保存点往返、祖先传播、失败 I/O、标签顺序以及禁用装饰器后的 Phase 1 字节兼容性。
