# ADR-004：SVG 读写边界与源路径策略

- 状态：已接受（当前 Phase 1 策略；未明确的细节待教师确认）
- 决定日期：2026-10-22
- 确认来源：用户明确选择“严格读入路径”及“只接受明确支持的子集；遇到不支持内容整条 `read` 失败”。

## 问题与候选

题目要求 `read`/`save`、缺 id 警告、SVG 往返、元素计数和 I/O 历史屏障，但未定义首次显式保存后的默认路径，也未承诺完整 SVG 标准兼容。直接由 CLI 读写 XML 会使文件格式、会话路径和历史混在一处；将文件访问与编解码作为两个跨模块端口注入会话虽可测试，却增添转发与组合负担。

## 决定

- 沿用 ADR-001：`editor` 定义一个文档存储端口，`svg` 实现文件与 XML 适配，`main` 装配；CLI 不访问文件或领域内部树。
- `init` 清除读入来源路径；`read <path>` 成功后才替换文档并设置来源路径；显式 `save <path>` 不改变来源路径；无参数 `save` 仅在已有来源路径时可用。失败不改变文档、路径或历史。
- 支持子集为根 `<svg>` 及 `rect`、`circle`、`ellipse`、`line`、`text`、`g` 六类元素；根尺寸与匹配的 `viewBox`，规定的几何属性，以及 `fill`、`stroke`、`stroke-width`。XML 声明和元素间格式空白不改变语义；文本元素只接受普通 XML 文本。其他元素、属性、变换、混合内容、CDATA、注释、DTD 等不静默忽略，整条读取失败。
- 读入先完整解析、校验并构造临时文档；缺 id 的警告仅在整体成功后输出。重复 id 失败；自动 id 不与显式 id 冲突。成功 `read/save` 才建立历史屏障。
- 序列化使用只读的图形投影及多态导出，不解析 `tree` 展示文本；SVG 导入所需的类型映射仍集中在图形工厂，不在 XML 适配器另设 `switch(tag)`。

## 取舍与复议

严格子集能防止读入后编辑产生未定义的视觉语义，但背景中的 `<g transform>` 示例会被拒绝。用户计划向教师确认；若该示例属于验收，应先定义变换下的 `move`/`scale`/跨父移动语义，再修订本 ADR 和测试，不以原样透传冒充完整支持。根尺寸格式、缺 id 编号规则和未展示的错误文本按可替换的保守策略实现，仍以题目和教师答复为准。
