# ADR-004：SVG 读写边界与源路径策略

- 状态：已接受（当前 Phase 1 策略；未明确的细节待教师确认）
- 决定日期：2026-10-22
- 确认来源：用户明确选择“严格读入路径”及“只接受明确支持的子集；遇到不支持内容整条 `read` 失败”。
- 复核：2026-10-23，用户确认第 0 节背景知识中的额外 SVG 内容暂不实现，并选择保留现有 Adapter 边界，不增加文件 API 注入层。

## 问题与候选

题目要求 `read`/`save`、缺 id 警告、SVG 往返、元素计数和 I/O 历史屏障，但未定义首次显式保存后的默认路径，也未承诺完整 SVG 标准兼容。直接由 CLI 或会话读写 XML 会使文件格式、路径和历史混在一处，因此两种候选都保留由 `editor` 定义的 `DocumentStore`：A 由一个 `SvgFileStore` 协调编解码与 Node 文件 API，用真实临时文件验证保存；B 另设可注入的文件操作对象，独立测试更多底层故障。B 增加构造、接口和协作成本，而当前没有第二文件后端，故选择 A；用户已确认该取舍。

## 决定

- 沿用 ADR-001：`editor` 定义一个文档存储端口，`svg` 实现文件与 XML 适配，`main` 装配；CLI 不访问文件或领域内部树。
- `init` 清除读入来源路径；`read <path>` 成功后才替换文档并设置来源路径；显式 `save <path>` 不改变来源路径；无参数 `save` 仅在已有来源路径时可用。失败不改变文档、路径或历史。
- 支持子集为根 `<svg>` 及 `rect`、`circle`、`ellipse`、`line`、`text`、`g` 六类元素；根尺寸与匹配的 `viewBox`，规定的几何属性，以及 `fill`、`stroke`、`stroke-width`。XML 声明和元素间格式空白不改变语义；文本元素只接受普通 XML 文本。其他元素、属性、变换、混合内容、CDATA、注释、DTD 等不静默忽略，整条读取失败。
- 读入先完整解析、校验并构造临时文档；缺 id 的警告仅在整体成功后输出。重复 id 失败；自动 id 不与显式 id 冲突。成功 `read/save` 才建立历史屏障。
- 序列化使用只读的图形投影及多态导出，不解析 `tree` 展示文本；SVG 导入所需的类型映射仍集中在图形工厂，不在 XML 适配器另设 `switch(tag)`。
- Adapter 采用现有 `DocumentStore` 客户端端口和 `SvgFileStore` 实现：`main` 注入真实存储，会话测试可注入存储替身；`SvgFileStore` 当前直接使用 Node 文件 API，只允许传入编解码器，不声称文件 API 也已注入。编解码由独立测试验证，文件替换与失败清理由真实临时目录验证。当前不另建文件操作端口；若出现第二后端、无法稳定复现的底层故障或保存规则显著增长，再比较该方案。

## 取舍与复议

严格子集能防止读入后编辑产生未定义的视觉语义，但背景中的 `<g transform>` 示例会被拒绝。用户已确认第 0 节“背景知识”中的额外 SVG 内容暂不实现；若教师明确将其列入 Phase 1 验收，应先定义变换下的 `move`/`scale`/跨父移动语义，再修订本 ADR 和测试，不以原样透传冒充完整支持。根尺寸格式、缺 id 编号规则和未展示的错误文本按可替换的保守策略实现，仍以题目和教师答复为准。
