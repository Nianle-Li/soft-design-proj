# ADR-009：属性处理器与原子 `set` 契约

- 状态：已接受并实现。
- 依据：Phase 2 §1、§3；Phase 1 的属性白名单、错误文本和撤销行为保持不变。

## 问题与方案

`AttributeHandler` 必须能为复合图形定义属性语义，同时不能取得文档索引、历史执行器或图形私有字段。一次处理还可能修改多个内部部件，失败时不得留下部分状态或历史。

| 方案                                           | 收益                                              | 代价与风险                                                             |
| ---------------------------------------------- | ------------------------------------------------- | ---------------------------------------------------------------------- |
| 处理器直接修改目标，另行提供补偿回调           | 接口直观                                          | 修改与补偿容易分离；处理器可能绕过文档收据，原子性和撤销粒度难以统一   |
| 处理器先返回可逆的 `PreparedSet`，文档统一应用 | 复用现有 `set` 收据和 undo/redo；成功前不产生历史 | 处理器须在准备阶段完成校验，并保证 `undo` 能恢复一次失败的部分 `apply` |

选择第二种。处理器只接收公开的 `Shape`、属性和值，通过公开方法准备一个 `PreparedSet`，不接收 `SvgDocument` 或历史执行器。`handles` 和准备阶段不得修改状态；`SvgDocument` 应用计划，成功后才签发一个收据。若 `apply` 抛错，文档立即调用同一计划的 `undo`，不签发收据并传播原错误。计划的 `undo` 必须既能撤销完整应用，也能恢复部分应用。

注册名称在 `attributes` 类别内唯一，重名报 `duplicate registration: attributes/<name>`。查询会评估所有处理器：无命中时调用图形原有 `prepareSet`，保持 Phase 1 白名单；恰好一个命中时只调用该处理器，准备或应用失败均不得回退；多个命中时在准备和修改前报 `multiple attribute handlers for <shape>.<attribute>: <names>`。显式拒绝歧义比按注册顺序覆盖更容易发现插件组合错误。

公共契约、注册表、文档调用与空注册表装配均已实现。`box` 处理器以同一 `PreparedSet` 契约传播 `fill`、`stroke`、`stroke-width` 与 `label`；配置加载通过统一安装事务发布处理器。测试覆盖唯一命中、无命中回退、多重命中、准备失败、部分应用失败、撤销与重做。
