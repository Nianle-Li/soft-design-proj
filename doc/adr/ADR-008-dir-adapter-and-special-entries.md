# ADR-008：`dir` 的目录端口与特殊项规则

- 状态：已接受并实现。
- 依据：Phase 2 §2.2–2.3；`dir` 无参数、只读当前工作目录、失败后会话继续。

## 决策

`dir` 插件拥有 `DirectoryReader` 端口。端口提供当前工作目录路径，并把该路径的直接子项转换为中性的 `directory`、`file`、`other` 三类；命令负责过滤、排序和题目规定的文本格式。Node 适配器是 Adapter，`node:process` 与 `node:fs` 是被适配接口，核心和 CLI 宿主不接触文件系统类型。

特殊项比较两种处理：

| 方案                               | 优点                                                                 | 风险                                                           |
| ---------------------------------- | -------------------------------------------------------------------- | -------------------------------------------------------------- |
| 跟随符号链接并按目标归类           | 链接可能像普通文件或目录一样显示                                     | 会访问链接目标、可能越过当前目录，断链与权限使结果依赖额外状态 |
| 按目录项自身类型归类，特殊项不显示 | 不遍历目标，结果只依赖当前目录项；符合题目只规定目录和普通文件的输出 | 用户看不到符号链接、套接字等特殊项                             |

选择第二种：符号链接及其他非普通文件、非目录项归为 `other`，`dir` 不显示也不遍历；`.` 和 `..` 即使由替身提供也忽略。目录在前、普通文件在后，各组用确定的字符串升序；隐藏项与普通名称相同处理。读取失败由命令统一转换为 `cannot read directory: <path>`，避免适配器泄漏平台错误文字。

测试使用端口替身覆盖混合项、隐藏项、空目录、稳定排序、读取失败及历史不变，并通过临时目录组合测试验证 Node 适配器。代码装配与配置装配均通过统一插件安装器接入该命令。
