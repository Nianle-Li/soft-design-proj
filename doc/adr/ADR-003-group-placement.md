# ADR-003：分组位置与顺序

- 状态：已接受（普通 `g` 的 Phase 1 `group`）
- 依据：`../../phase_cli_1.md` §3、§4.2、§4.3、§6；`../requirements.md` 的 `REQ-024`、`INV-002`、`INV-006~009`、`AMB-006`。

## 问题与候选

题目要求从各自原父容器摘出目标，保持相对顺序，但没有规定新组的父级与位置，尤其没有定义跨父目标的共同顺序。方案 A 将新组置于目标的最近共同父级，放在该父级中最早所选目标所在分支的原位置；成员按分组前文档的深度优先顺序排列。画布根也可作为共同父级。方案 B 总是将新组追加在画布根级，成员仍按原文档顺序排列。

两者均可保持被选目标的相互顺序，且仅由 `model` 负责树结构与 id 索引，`editor` 保存本次命令的局部撤销凭据。方案 B 实现较短，但同父嵌套图形被分组后也会跳出原父级，改变继承样式与编辑归属。方案 A 计算共同父级的代价较高，却更好保留原有局部结构，因此采用方案 A。两者都无法保证未选目标与被选目标之间原有的绘制交错顺序，分组操作本身必然可能改变这种关系。

## 决定与边界

同父目标的新组留在该父级，位于原先最早被选成员的位置；跨父目标的新组位于最近共同父级、最早被选目标所在分支的位置。无论命令参数次序如何，成员都按操作前文档深度优先顺序排列。选中容器视为选中整棵子树；不得同时指定该容器及其后代。新组 id 必须唯一；任何失败不得改变树或编辑历史。

`SvgDocument` 先完成目标、重复项和祖孙关系校验，再计算成员顺序、共同父级及原位置；结构变化由 Receiver 一次应用。撤销只需新组引用、位置以及每个成员的原父节点和原索引，不保存整份文档；一次 `group` 只占一个历史单元。`cli` 只做参数解析与反馈，`editor` Command 不计算树位置。既有 `cli → editor → model` 依赖方向不变，不增加模块或模式。

## 验证与复议

- 同父、跨父、根级与嵌套分组；参数逆序时仍按原文档顺序；新组位置按共同父级规则。
- 原组子树可继续寻址；undo 精确恢复所有原父级和顺序，redo 再次得到相同树；历史以整条命令为单位。
- 重复新 id、缺失目标、重复目标、容器与后代同时出现时原子失败，失败不改变 undo/redo 状态。
- SVG 往返测试验证分组后的嵌套和顺序；若位置规则的要求变化，再复议本 ADR。
