# ADR-012：插件清单校验与安装事务

- 状态：已接受，按切片实施。
- 依据：Phase 2 §6；加载失败不得退出，当前插件全部回滚，先前成功插件保留。

## 决策

比较两种方案：

| 方案                                                       | 收益                                               | 代价与风险                                                             |
| ---------------------------------------------------------- | -------------------------------------------------- | ---------------------------------------------------------------------- |
| 插件直接写入四个运行注册表，失败后逐项删除                 | 初始代码少                                         | 四个注册表都要暴露删除和枚举；激活中途的状态可见，回滚知识泄漏到加载器 |
| 每次激活写入私有暂存上下文，校验成功后一次性并入已接受列表 | 失败天然不可见；同一安装路径可供代码和配置装配复用 | 运行注册表要在全部安装完成后构造                                       |

选择第二种。`PluginInstaller` 是宿主装配模块：它持有按安装顺序排列的四类已接受实例，每次 `install` 创建一次性暂存上下文。插件只能通过公开 `PluginContext` 注册；激活成功后先检查与既有名称的冲突，再比较 `contributes` 声明和实际暂存的类别及名称集合，全部通过才公布本插件的四类贡献。失败只丢弃当前暂存，既有贡献保持不变。

清单四类缺省为空，集合比较不受声明顺序影响；诊断按 `shapes`、`commands`、`decorators`、`attributes` 固定顺序输出，并对类内名称排序，使 A/B 装配得到相同错误。插件重复调用注册方法或与先前贡献重名，均报题目规定的 `duplicate registration: <category>/<name>`，不包装为激活异常。除此之外的激活异常统一为 `plugin failed to activate: <name> (<reason>)`。`options` 原样作为只读未知值传给激活函数，由插件自行验证；安装器不解释插件专属选项。

`PluginContext` 和 `Plugin` 是插件可见的安装协议而非第五个业务扩展点，放入核心公开立面；事务实现、清单类型和模块解析仍属于 `src/host/assembly/`。配置加载器后续只负责配置验证、按序解析模块、读取包清单和错误分类，再调用同一个 `install`。动态模块求值失败不得误报为顶层模块不存在；该分类在加载器切片以独立测试确定。

配置结构先由独立解析边界归一化为有序的启用项：根必须含 `plugins` 数组，每项必须有非空字符串 `module`，`enabled` 若出现只能是布尔值；`enabled: false` 项不进入加载序列，`options` 保持 JSON 值并由插件解释。语法或结构错误只暴露 `invalid plugin config`，是否回到默认装配由调用它的加载流程统一决定。

## 验证边界

- 一个测试插件同时注册四类贡献，验证顺序和 options 透传。
- 分别验证清单不一致、激活中途抛错、插件内重名及与先前插件重名；失败后快照不含当前插件，后续插件仍可安装。
- 本切片不读取 `plugins.config.json`、不动态导入模块、不修改组合根，也不声称已完成方式 B。
