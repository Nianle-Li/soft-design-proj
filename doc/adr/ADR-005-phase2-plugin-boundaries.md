# ADR-005：Phase 2 CLI 核心、宿主与插件边界

- 状态：已接受并实现。
- 日期：2026-11-23。
- 范围：CLI 插件式重构。VSCode 扩展保持独立交付，Phase 1 的 [ADR-001](ADR-001-module-boundaries.md) 保留为重构前事实。
- 权威依据：`pj1-phase2/phase_cli_2.md` §1–7 约束新增功能与验收，`phase_cli_1.md` 约束原有命令、输出及 §4.4 的 `box` 语义。

## 要解决的问题

Phase 1 将命令名集中在 `CliApp`、图形类型集中在 `ShapeFactory`，`ShapeSpec` 封闭列出六种图形，`SvgDocument` 直接构造并辨认 `GroupShape`。这些位置曾符合 Phase 1 范围；Phase 2 要求四个内核侧扩展点、可单独启停的插件、两种装配方式、`box` 的整棵子树创建与读回，以及新增插件不改内核和既有插件。`final` 的两段会话标准输出及保存 SVG 已作为字节夹具冻结。

必须保持：六种旧图形和旧命令默认可用；禁用所有可选插件仍保持旧行为；一次编辑一个 undo 单元；失败不改文档及历史；`read` 失败不替换当前会话；旧输出、错误和 SVG 字节不因框架化改变。新增 `dir` 无文档也可运行，且不改变工作目录或历史。

插件市场、远程下载、任意 SVG 标准覆盖、额外遍历框架及第五业务扩展点不属于本项目边界。插件包名解析是题目要求的本地运行环境模块解析，不等同于发布 npm 包。

## 变化点与候选方案

| 变化点                       | 预期                        | 架构准备                                                                  |
| ---------------------------- | --------------------------- | ------------------------------------------------------------------------- |
| 新图形及复合子树             | 高；题目必做 `box`          | `ShapeProvider`、通用子树校验与读回路径，内核不识别 `box` 名字            |
| 新命令                       | 高；题目必做 `stats`、`dir` | `Command` 注册与插件自有帮助/参数规则；无文档命令不经编辑历史             |
| 属性语义与树标签             | 高；题目各必做两个实例      | `AttributeHandler` 的受控修改端口、`TreeDecorator` 的稳定行上下文与组合点 |
| 插件集合、顺序、options      | 高；题目必做 A/B            | 宿主装配和配置加载最终走同一注册事务                                      |
| 另一种 XML 库、另一种 CLI UI | 可能但非题目目标            | 保持适配器及宿主与核心的单向依赖；不为此预建额外协议层                    |

比较过的 A+ 保留 `src/model`、`src/editor`、`src/cli` 等现有目录，并增设受控插件 API；它能满足题目，但“内核”横跨多个目录，现有 CLI 表现知识仍容易被视作核心。原始 B 只把文件搬进 `core`，没有改善职责。**选择 B+**：保持 A+ 的公开面、机械依赖检查与注册事务，同时按职责将领域/应用策略、CLI 表现、文件适配和具体插件分开。它的收益来自依赖图与知识归属，不来自目录名称本身。多 npm workspace 包的方案隔离更强，但题目无发布要求，包构建与模块解析层会增加无关契约，暂不采用。

| 评估面                  | A+：原层次与受控公开面                                                     | B+：职责重划与受控公开面                                          | 多 workspace 包                        |
| ----------------------- | -------------------------------------------------------------------------- | ----------------------------------------------------------------- | -------------------------------------- |
| 内聚与分层              | 模型/历史仍可独立，但 `cli` 同时承载应用扩展和文本表现，需额外解释逻辑核心 | 模型、编辑、命令选择、树装饰契约与 CLI 表现分开，邻层提供不同抽象 | 可做到同样分层，另加包边界             |
| 插件接口宽度与依赖      | 单一公开面和检查器可以限制导入                                             | 同样限制；物理核心边界让禁向依赖更易审计                          | `exports` 强制包级入口，仍需设计窄契约 |
| 测试缝与替换            | 四扩展点、文件适配和 CLI 可独立测试                                        | 相同；可单独检查核心不含 CLI/文件系统细节                         | 相同，测试运行须跨包配置               |
| 新插件的改动传播        | 插件及一处代码装配或配置；核心和旧插件不改                                 | 相同，且目录判据更清楚                                            | 相同，可能伴随依赖元数据变更           |
| 实施与认知代价          | 初始搬迁少，但核心范围需持续靠文档和规则解释                               | 初始搬迁多；完成后新读者更易定位职责                              | 构建、模块版本和包发布关系增加额外概念 |
| 后续新增 I/O 或呈现方式 | 已有适配边界可扩展                                                         | 宿主与适配器位置更清晰，核心不因呈现方式改变                      | 同样可扩展；课程范围内优势有限         |

若仅比较最终架构，B+ 的职责边界略优；迁移成本不是 Phase 2 的明示评分项，但实施中仍必须保证每次提交可运行、可回归。B+ 不应通过引入空转的 `framework` 层或发布包来追求目录整齐。

## 目标模块与依赖规则

| 路径                                  | 拥有的知识与对外契约                                                                                                       | 允许依赖                                                        | 禁止依赖                                               |
| ------------------------------------- | -------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------- | ------------------------------------------------------ |
| `src/core/model/`                     | `Shape`/容器抽象、`SvgDocument`、只读图形视图、`ShapeProvider` 与 `AttributeHandler` 契约和选择机制；文档 id/父子/原子操作 | 本模块                                                          | 编辑器、宿主、适配器、插件、XML/文件 API               |
| `src/core/editor/`                    | `EditorSession`、编辑 `EditCommand`、`CommandExecutor`、`DocumentStore` 端口和 I/O 栅栏                                    | 核心模型                                                        | 宿主、适配器实现、插件                                 |
| `src/core/command/`                   | REPL 插件 `Command` 契约、按名称注册/查询、供插件使用的最窄命令上下文                                                      | 核心模型、编辑器公开类型                                        | CLI 解析器/格式器、宿主、插件实现                      |
| `src/core/tree/`                      | `TreeDecorator` 与树行渲染接口、组合点所需的只读行上下文                                                                   | 核心模型的只读视图                                              | 具体格式器、宿主、插件实现                             |
| `src/core/plugin-api.ts`              | 只重导出插件需要的四契约、基础图形/容器抽象、只读视图与受控操作；插件唯一核心入口                                          | 上述核心模块                                                    | 宿主、适配器、具体插件；核心运行模块反向导入此汇总入口 |
| `src/host/cli/`                       | `CliApp`、命令行解析、旧命令文字、帮助排列、树行格式、REPL 文本协议                                                        | 核心公开能力                                                    | 模型内部可变字段、具体 XML 库、任何可选插件实现        |
| `src/host/assembly/` 与 `src/main.ts` | 默认内置装配、代码装配入口、配置加载、模块解析、清单校验及错误汇总                                                         | 核心、适配器、内置实现、插件                                    | 图形业务规则；加载器硬编码插件名或导入                 |
| `src/adapters/svg/`                   | `SvgCodec`、`SvgFileStore`，XML 与磁盘 API 到领域读写契约的翻译                                                            | 核心模型及编辑器 `DocumentStore` 类型端口                       | 宿主、插件实现、编辑器历史                             |
| `src/builtin/shapes/`                 | 六种旧图形的具体类与提供者，默认注册但走同一图形选择机制                                                                   | `core/plugin-api`                                               | 宿主、可选插件、核心内部路径                           |
| `plugins/<name>/`                     | 可选插件类/实例、清单、各自的局部适配器；`stats`、`dir`、`box`、树标签彼此独立                                             | `core/plugin-api`、自身文件；`dir` 的 Node 适配器可使用文件 API | 宿主、核心内部、既有插件实现、SVG 适配器               |

核心内部定义契约，不导入 `plugin-api.ts` 汇总入口；该入口是向外限制可见性的立面，不能演变为业务转发层。宿主可为装配导入必要的核心构造器，插件只能用公开入口。`src/builtin/shapes/` 是内置实现而非内核；旧命令的 CLI 文字实现归 `src/host/cli/`，由宿主注册到同一个 `Command` 注册机制。`stats` 插件独立于此内置命令表。

插件使用 Node 内置 API 的文件放在自身 `adapters/` 下，命令与图形实现通过本插件的适配器访问外界。插件的第三方运行依赖在本插件的 `package.json` 声明供依赖检查器识别；该文件是本地依赖边界元数据，不要求把项目改为 npm workspace。运行时依赖仍须按实际模块解析环境安装。

依赖检查器扫描 `src/`、`plugins/` 与 VSCode 扩展源码，识别静态导入和动态导入，仅在宿主加载器中允许受控动态模块路径。第三方包、Node API 和类型专用端口均按模块显式放行，不保留宽泛兼容例外。[Phase 1 组件图](../assets/architecture.plantuml)记录基线架构，[Phase 2 组件图](../phase2/architecture-after.plantuml)对应最终实现。

## 关键契约的边界条件

- **图形**：提供者可构造分离的完整子树；文档在接入前遍历全部节点检查 id、父子关系及容器规则，成功后整体接入并保存局部逆操作。`box` 通过公开图形创建上下文请求默认 `rect`、`text` 提供者，不导入它们的具体类；独立测试可用提供者替身。普通 `group` 的 `g` 也经已注册的内置提供者创建，不让 `SvgDocument` 继续 `new GroupShape`。容器“可收纳子节点”与“可解组”分开，避免 `box` 破坏替换关系。
- **SVG**：XML 适配器把 DOM 转成不泄漏解析器类型的只读元素输入；提供者负责其类型的参数/属性及子树读回。分派机制可先查看通用扩展标记，再按 SVG 标签选择；未注册语义标记时可回退到普通 `g`，但普通 SVG 的未知属性仍须按 Phase 1 规则拒绝。读入整份文档成功后会话才替换，序列化继续从图形只读 SVG 视图生成。
- **命令**：`Command` 是外部命令名、帮助、参数规则与执行契约；已有 `EditCommand` 是可撤销编辑请求，二者不合并。`Command` 的返回值由 CLI 宿主按旧格式输出，`dir` 可在无文档上下文执行。旧命令也经注册表分派，不能在 `CliApp` 留一个第二套名字 `switch`。
- **树**：只读树投影提供稳定的类型、容器及语义事实，插件不解析 `label` 字符串。树行基础渲染器位于宿主；`TreeDecorator` 针对语义行目标贡献可选标签，注册表按登记顺序查询和组合，未注册时保持原渲染结果。该机制保留了独立附加行为的装饰意图，但没有让插件包装格式化器或共享完整渲染接口；保存点和祖先传播语义见 [ADR-010](ADR-010-tree-decoration-and-dirty-semantics.md)。
- **属性**：处理器只经受控目标访问及可回滚的局部修改协议工作。文档 Receiver 负责一次 `set` 的整体成功/回滚，`CommandExecutor` 只在成功后入历史。处理器失败不走默认属性规则。公开访问方式、多个处理器冲突规则和实际事务协议在属性 ADR 中确定。
- **装配**：代码与配置入口调用同一个单插件安装函数。该函数暂存四类注册、按清单校验和查重，成功才公布；失败丢弃当前插件暂存，之前成功插件不受影响。配置加载器只做通用模块解析与错误分类，不按插件名分支；非法配置回到默认内置能力。校验时机、options 传递及模块求值错误识别在装配 ADR 中确定。

## 模式协作、代价与验证

| 模式或扩展机制                 | 必要性、角色与协作                                                                               | 拒绝的简化/代价                                                     | 能识破表面实现的测试                                         |
| ------------------------------ | ------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------- | ------------------------------------------------------------ |
| Command                        | `EditCommand` 绑定请求和 Receiver，`CommandExecutor` 管历史；新 `Command` 注册表统一调用可选命令 | 不建第二套历史；注册表增加一层选择逻辑                              | 失败后历史不变、`dir` 无文档执行、禁用命令回到未知命令       |
| Composite                      | 核心容器契约使 `g`、`box` 与叶子统一参加树操作，具体类负责自身不变量                             | 容器接口不能承诺所有容器可 `ungroup`                                | `box` 嵌套/移动/撤销及必要子部件保护；内核无 `box` 分支      |
| Adapter                        | `dir` 的目录访问端口由命令客户端拥有，Node 目录访问是 Adaptee，插件内适配器翻译结果              | 增加一个可替换端口，避免命令直接读取磁盘                            | 替身覆盖排序/失败，真实临时目录测试同一命令类                |
| 树标签装饰扩展（非经典包装链） | `TreeDecorator` 读取语义行目标并贡献标签，注册表按顺序组合，格式化器仍独占树遍历与排版           | 不采用包装完整格式化器的 GoF 结构，避免向插件泄漏枝线与列对齐等知识 | 双标签顺序、禁用后旧 `tree` 字节、接入新标签时渲染器差异为空 |

单次 DFS 不抽象为 Iterator；新增图形是主要变化轴，因此不采用需要枚举全部类型的 Visitor。dirty 通过成功的生命周期操作重置保存点基线，不引入通用事件总线。

## 控制流与验证门禁

1. `create`：宿主解析输入 → 核心命令注册表选内置 create → 提供者构造候选子树 → 文档完整验证并接入 → 编辑命令保存局部凭据 → 宿主生成原有反馈。若提供者或预检失败，文档和历史不变。`undo`/`redo` 用该局部凭据撤下/恢复整棵子树；不得保存整份文档快照。
2. `read`：SVG 适配器解析为只读输入 → 提供者还原候选文档 → 全部成功后 `EditorSession` 替换当前文档并设置 I/O 栅栏。`save` 从图形只读视图经适配器写盘，旧会话的输出与 SVG 原始字节必须保持 `final` 基线。
3. 新增 `box`：只新增 `plugins/box/**`，代码方式改一个 `src/host/assembly/` 顶层文件，配置方式只改配置及必要元数据；核心、旧插件、加载器不改。其子部件 id 冲突、读回降级和属性撤销另有独立测试。
4. 新增树标签：只新增插件和装配/配置；`src/core/` 与 `src/host/cli/TreeFormatter.ts` 不改。更换 SVG 文件适配实现则只涉及 `src/adapters/svg/` 与宿主装配，不修改核心领域规则。
5. 检查器具有合法和非法导入的独立测试；各扩展点具有注册、调用、禁用与违规契约测试；加载器覆盖题目列出的故障、回滚和继续加载；A/B 装配在插件集合、顺序、options、输入和工作目录一致时比较原始字节。`Phase1FinalBaseline.test.ts` 验证全部 Phase 1 基线行为。

指标脚本以 `final` 基线和发布版本计算：`src/core/` 归内核，`src/host/`、`src/adapters/` 和 `src/main.ts` 归装配与技术支持，`src/builtin/` 与 `plugins/` 归实现插件，VSCode 扩展单独统计。四个扩展点、插件 API、模块解析及依赖规则均有契约测试、反例测试和机械门禁；属性、box、dirty、装配及 `dir` 的细化决策分别记录于 ADR-008 至 ADR-012。
