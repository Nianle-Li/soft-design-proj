# Phase 2 开发流程与门禁

本文件记录 Phase 2 的开发与收尾门禁；[需求与验收矩阵](requirements.md)记录要求—证据状态，[实验报告](../README.md)陈述最终设计与结果。Phase 2 题目约束新增行为，Phase 1 题目继续约束原有命令和输出。已发布的 `final` 不移动；只有交付核验完成后才创建一次 `p2`。

## 每个切片的工作规则

1. 核对题目原文、精确输出、失败后状态及 Phase 1 兼容边界；未定义语义先形成 ADR。
2. 对重要设计比较至少两种可行方案，按依赖方向、信息隐藏、可替换性、测试性与新增层成本选择。
3. 先建立能发现缺陷的正常、错误、边界和禁用测试，再做最小实现。
4. 验证类型、Lint、格式、依赖、追踪范围、独立测试、全量回归和 Phase 1 逐字节基线。
5. 仅把可复用的设计判断、验证证据和 AI 建议纠偏记入 [关键证据与设计记录](record.md)，不写聊天流水账。
6. 每个可独立验收的能力设计内聚提交；提交、推送和标签操作均须用户明确确认。

## 兼容性与装配验证

- `final` 的 Phase 1 完整会话、标准输出和保存 SVG 作为原始字节基线；禁用可选插件时必须逐字节相同。
- A/B 装配使用相同插件集合、顺序、options、输入、初始文件和固定工作目录；日志不写入 `dir` 的目标目录。
- 加载器覆盖模块缺失、无默认导出、清单不符、激活异常、重复注册、非法配置、回滚和失败后继续。
- 属性处理器覆盖多重匹配、一次 undo 单元、部分应用失败与 redo 失败回滚。
- 方式 A 的接入差异以 `0342080` 核验；方式 B 由仓库根 `plugins.config.json` 和生产加载器测试提供，提交后记录其提交号并运行题目规定的差异命令。

## 最终指标与不可移动标签

指标脚本只统计 Git 中的 CLI 内核、装配与技术支持、内置及可选插件和 VSCode 源码，排除测试、文档和生成物。收尾顺序为：

1. 完成功能、报告、真实截图和全部质量门禁，形成候选提交。
2. 从候选 `HEAD` 读取源码，以 `--target-label p2` 生成并提交 `docs/metrics/metrics.md`。
3. 确认最终提交后创建 `p2`，不得移动 `final`。
4. 从真实 `p2` 重跑指标到临时文件，与已提交结果逐字节比较；差异必须为空。
5. 推送最终分支与 `p2` 后，通过远端引用再次核对。

该顺序避免先打标签再补交指标，也不需要移动 `p2`。
