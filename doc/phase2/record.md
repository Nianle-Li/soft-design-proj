## CLI B+ 架构选择

- `ShapeSpec` 是六种类型的封闭联合；`SvgDocument.create` 只检查根 id，`undoCreation` 拒绝非空容器；`SvgCodec` 对未知属性直接报错。因而只在 `ShapeFactory` 外加注册表无法满足 `box` 的整棵子树创建、撤销及 `data-kind` 读回。用户选择 B+：按职责分开核心、CLI 宿主、SVG 适配与插件，并以受控插件公开面和机械规则验证依赖；详见[ADR-005](../adr/ADR-005-phase2-plugin-boundaries.md)。
- 复核 Phase 2 §1、§6–7：迁移文件数和工时不是明示评分项；验收看扩展行为、依赖方向、接入提交差异与可复现证据。此前偏重迁移成本的推荐已修正；B+ 的优势在于把 CLI 表现知识移出核心，而非仅改目录。四扩展点签名及未规定的语义仍待各自 ADR 和测试。
- B+ 依赖门禁先于运行模块迁移：检查器扫描 `src/` 与 `plugins/`，用反例锁定插件唯一核心入口、加载器动态导入例外及 SVG 的类型端口；旧目录仅作迁移期白名单，迁走时须逐项删除。插件第三方依赖由本插件 `package.json` 声明，Node API 仅在本插件 `adapters/` 使用，避免把 I/O 藏在命令或图形实现里。此时尚无插件实现，检查器测试使用临时目录夹具。
- CLI 文字知识由 `src/cli/` 整体迁入 `src/host/cli/`：解析器、树格式器和 `CliApp` 一起搬迁，避免过渡期旧目录反向依赖新宿主；同时删除旧 `cli` 检查器白名单。Phase 1 报告的原路径仍是 `final` 时点的历史事实。此切片只改导入与路径，不改变命令分派或反馈内容。
- SVG 编解码与文件存储一起迁入 `src/adapters/svg/`，仍只以类型导入依赖编辑器的 `DocumentStore`；迁移期间对旧模型路径的依赖由检查器限定，待模型迁移时收紧。同步删除旧 `svg` 白名单，不改变 XML 子集规则、错误反馈或保存字节。
- 编辑器的 15 个文件作为一个模块迁入 `src/core/editor/`：会话、操作命令、历史、只读投影与存储端口保持原有协作，避免为分批搬迁扩大旧目录的反向依赖白名单；宿主和 SVG 适配器仅改导入路径。`src/core/editor/` 对旧模型路径的依赖仍属下一次模型迁移的过渡规则，旧 `editor` 白名单已删除。
- 用户确认 C+ 图形扩展方向：提供者只构造分离树，文档统一校验、接入与局部撤销；容器用无副作用的预检保护必要子部件，`group` 在移动任何节点前检查全部目标。SVG 标签与插件语义类型分开，避免树标签从显示文字反推类型。现阶段这是待测试实现的架构决策，不是已完成能力；详见[ADR-006](../adr/ADR-006-shape-provider-and-model-split.md)。
- 整树接入的首个实现切片在现有 `SvgDocument` 增加 `createCandidate`：接入前遍历分离树，检查节点身份、环、内部及外部 id 冲突，成功后一次索引全部节点；收据只保存根位置和本次成员身份，整树撤销/重做不复制文档。旧 `create` 复用同一路径。测试覆盖嵌套索引、冲突失败不改树、整树撤销/重做及撤销顺序错误；真实提供者注册、容器保护和模型迁移仍待后续切片。
- 提供者创建契约先在迁移期 `src/model/ShapeProvider.ts` 定义，由注册表按类型选择并把受控的子图形创建能力交给它组合；提供者返回的根 id 必须与请求相同，文档仍负责整树校验和接入。编辑会话可注入注册表；当时旧六种图形仍由原工厂处理，为避免同名提供者静默覆盖旧图形，会话构造时暂拒绝这些重名。省略可选提供者即为禁用。测试覆盖选择、组合、禁用、重名、一次 undo/redo，以及提供者抛错或候选树失败后保留 redo。该切片尚未完成内置图形注册化、公开插件入口、SVG 读回或容器约束，不能据此将 E1 标为完成。
- 容器约束切片把有序子节点和通用整体编辑下沉到 `ContainerShape`，普通 `GroupShape` 只保留 `g` 语义。比较过让插件继承具体 `GroupShape` 与依赖容器抽象：前者会使插件依赖内置实现，故选后者。容器的 `assertCanDetach`、`assertCanUngroup` 是无副作用预检；文档在直接 `delete`、`addto`、`group` 及移除目标容器的 `ungroup` 前检查父容器，`group` 先检查全部目标；`ungroup` 还先检查目标容器许可，再检查根级限制。假受保护容器测试覆盖失败状态、redo 历史、整棵容器操作及普通组兼容；目前仍在迁移期 `src/model/`，文档内的 `group` 构造尚待改用注册的普通组提供者。
- 模型迁移比较了整目录搬入内核与先搬闭合抽象子图：前者会把六种具体图形及中央工厂带入内核，故先将 `Shape`、`ContainerShape`、样式、视图、错误及创建契约等八个文件迁入 `src/core/model/`；删除编辑器里仅转发错误和树视图的两个薄层。依赖检查器只增加迁移期 `src/model/ → src/core/model/` 方向，并以反例拒绝反向导入；其余旧模型实现、文档和工厂仍待拆分，不能把本次路径调整视为插件化完成。
- 公开插件入口 `src/core/plugin-api.ts` 只重导出当前提供者需要的核心抽象和领域错误；普通 `g` 具体类移入 `src/builtin/shapes/`，其提供者按 Phase 1 语法拒绝多余参数。测试证明提供者可经共享注册表构造并接入普通容器。旧 `ShapeFactory` 与 `SvgDocument.group` 暂仍直接构造 `GroupShape`，依赖检查器只对这两个精确路径放行旧模型到该内置类的导入；默认注册与经提供者执行 `group` 是下一切片，不能把本次提供者测试误报为完整装配。
- 默认装配选择由 `host/assembly` 创建内置 `g` 注册表，而非让核心创建具体类：宿主知道内置实现，核心只接收注册表；可选同名提供者由注册表拒绝。CLI 初始化与 SVG 读回使用同一注册表，`create g` 和 `group` 均调用提供者；`group` 在移动目标前要求返回空的 SVG 容器，失败不改文档。旧单测和独立 `SvgCodec` 仍可无注册表构造，暂由原工厂处理 SVG 读入与其他旧图形；待其余图形迁移后再收紧两处精确依赖例外，不能将当前切片视为全部内置图形注册化。
- `rect` 迁移比较了让新提供者继续调用旧 `ShapeFactory` 与把具体类移入 `builtin/shapes`、由提供者持有自身 CLI 参数规则：前者使内置模块反向依赖迁移期模型，并保留中央类型分支，故选后者。公开入口只增添 `RectShape` 已需的样式及操作类型；默认装配注册 `rect`，旧工厂仅为 typed 创建和 SVG 读入暂时直构该类，依赖例外仅限 `ShapeFactory → RectShape`。参数、填充色、无效数值和尺寸及失败后 redo 均以测试约束；其他四种叶子与读回契约未迁移，E1 仍未完成。
- 对 `rect` 提交的粒度复核：16 个文件中含类迁移后的多处测试导入更新，新增运行行为仅是一个图形的默认创建，测试与旧会话可独立回归，故数量本身未使该提交失去内聚性；但它同时包含结构搬迁与行为接入。依据迭代课件的短周期可执行增量及重构课件对结构/行为分离的提示，后续先以纯搬迁提交迁移 `CircleShape`，再另行提交提供者和默认注册。两步各自保持可运行，并分别验证依赖边界与 Phase 1 字节基线；PPT 只用于评估提交粒度，不增加题目要求。
- `circle` 在类搬迁之后单独接入提供者：默认装配通过注册表创建，独立注入可替换其行为，错误及失败后的 redo 由测试约束。其数字参数解析与 `rect` 当前有两份相同逻辑；在后续叶子继续接入前，宜先以纯重构切片抽取内置提供者共用的参数规则，避免多个提供者各自维护相同错误格式。此处仍未实现 SVG 读回提供者契约。
- 内置提供者共用参数规则比较了继续各自复制数字检查与抽取内置模块内部的纯函数：后者把 Phase 1 的参数个数和有限数字错误格式固定在一处，不扩大 `plugin-api`，也不让提供者依赖旧 `ShapeFactory`。`rect` 与 `circle` 的空白、非有限数和参数个数测试在抽取前后均通过；各类专有的尺寸/半径及填充色验证仍留在图形对象和提供者。
- `line` 提供者对四个坐标使用共用有限数字规则，对可选 `stroke` 调用图形既有 `prepareSet` 校验；属性保存在 SVG/详情中，Phase 1 的树行仍只显示线段几何，不额外显示描边。默认注册与替换提供者的测试、失败后 redo 以及逐字节会话共同约束这条兼容路径。
- 六种内置图形均经默认注册表创建后，比较保留编辑会话的旧工厂重名检查与删除该过渡检查：前者使核心继续认识具体类型清单，且与注册表的重复注册校验重叠；选择删除，默认装配仍拒绝可选同名提供者，显式注入的注册表则可替换内置行为。`text` 测试覆盖空文本、特殊字符、非法参数、替换、撤销/重做及失败后 redo；旧工厂仍承担无注册表时的回退、typed 创建和 SVG 读回，故 E1 尚未完成。
- SVG 读回契约比较把 DOM 交给图形提供者与传递中性输入：后者隔离 XML 解析器，输入只含标签、已分配 id、属性、直接文本与已读好的子图形。注册表校验读回对象和根 id，文档随后负责整树检查；`readSvg` 在内置图形迁移期可选，以保持现有读回路径可运行。本切片仅固定公开契约和假提供者测试，`SvgCodec` 尚未调用它，不能据此声称插件读回已实现。
- `SvgCodec` 接入读回时比较立即改写全部图形为统一递归构造与只在有读回方法的提供者处分离子树：前者会同时改变旧图形的校验/错误顺序，故过渡期选后者。假提供者测试证明旧 `g` 下的新标签、嵌套新标签、内置子图形、缺失 id、重复 id 拒绝和读回失败后保留当前会话及撤销历史；具体 `box` 的 `g` 语义标记及异常结构规则仍待其 ADR，不能用这个自定义标签测试替代 box 验收。
- 普通 `g` 读回比较继续由中央 `ShapeFactory` 构造与由内置提供者构造：后者使默认装配真正验证容器读回，且允许在其子树中组合其他提供者。公共的 SVG 属性白名单、缺失几何值和显式样式恢复规则留在内置模块私有辅助函数，`g` 只处理自身标签、子节点与容器语义；不扩张插件公开入口。嵌套顺序、缺失 id、样式归一化、XML 字节及单项错误与旧路径对照；其余五种图形仍待迁移。
- `rect` 读回比较复制数字/尺寸校验与复用自身 `create`：后者让命令创建和 SVG 读回共享几何不变量，SVG 属性白名单、缺失值及显式样式由内置辅助函数处理。对照旧路径验证了嵌套、缺失 id、零尺寸、三项样式、编码字节、缺失/非法属性和叶子收纳错误；其余四种叶子仍待迁移。
- 三种数值叶子共用 SVG 属性/样式规则，同时保留各提供者自身的几何与 `circle.r`、`ellipse.rx/ry`、`line.stroke` 校验；合并为一笔可独立验收的读回切片。对照测试发现旧 `importShape` 在非法叶子父节点下报 `no such container`，而此前提供者读回复用编辑用 `createCandidate` 报 `not a container`。选择新增无编辑收据的 `importCandidate` 并复用旧导入父节点检查，保留旧错误及整树 id 校验；不以吞错或改 CLI 文案掩盖差异。`text` 的子元素错误须另行处理。
- `text` 与数值叶子分开迁移：空文本、空白与转义字符须原样读回，且 Phase 1 对 `<text>` 内任何元素优先报 `unsupported child element in <text>`。现有中性读回契约先构造子图形，若只在提供者内检查，`<tspan>` 会先报未知标签。比较扩大公共预检接口、改惰性子节点协议与适配器保留这一条既有 XML 子集检查，选择最后者以避免为单个错误扩张全部提供者接口；提供者直接调用时也检查子节点。对照旧路径的文本、样式、编码与单项错误后，六种内置读回均已接入；旧工厂与过渡回退仍待独立清理。
- 六种内置读回已具备后，配置了注册表的 `SvgCodec` 改为只按注册类型递归读回：否则缺少提供者仍会被旧工厂静默补上，无法验证禁用/装配契约。缺少类型保持 Phase 1 的 `unsupported SVG element`，已注册但无 `readSvg` 给出明确契约错误；假插件测试显式加入所需内置提供者。无注册表的直接构造路径仍保留旧工厂，待其调用方与 typed 创建另行迁移，不把本切片误报为工厂已删除。
- `EditorSession.create(type, …)` 在配置注册表后只按注册类型创建，缺失类型不再回退旧工厂。假提供者测试显式追加所需内置提供者，空注册表则证明该入口的禁用效果可观察；`group`、typed 创建及无注册表会话仍有旧路径，E1 尚未完成。
- `group` 原先在已配置注册表缺少 `g` 时仍直接构造旧分组，和创建/读回的禁用语义矛盾。现改为让注册表明确拒绝；反例先证实旧回退会成功，随后验证失败不改树且 redo 可继续。无注册表分组和 typed 创建仍待迁移。
- 测试共用的 `createFromCommand` 原先通过旧工厂解析命令并走 typed 创建，使大量模型测试继续依赖封闭类型分派。现由宿主默认提供者构造分离图形，再用文档的候选树接入；自定义 `frame` 提供者反例先证明旧辅助入口无法扩展，迁移后可用。生产 typed API 的数字与样式语义未由 CLI 参数转换替代，仍须另定迁移边界。
- `SvgFileStore` 的无参默认值会暗中建立无注册表的 `SvgCodec`，使技术适配器默许旧工厂读回。改为调用方显式提供 codec；测试装配辅助入口使用六种内置提供者，生产入口原已显式注入。构造签名改变先让类型检查指出全部 14 处测试调用，逐处迁移后恢复；`SvgCodec` 自身的无注册表旧入口仍待后续切片退出。
